## 一、为什么重写(原 Godot 项目放弃)

原 Godot 4.3 项目连续 4 版(v1.0.21~v1.0.24)在用户手机上**横屏锁定全部失败**:

| 版本 | manifest screenOrientation | 结果 |
|---|---|---|
| v1.0.22 | 12 (userPortrait,Godot 映射 bug) | 竖屏 letterbox |
| v1.0.23 | 6 (sensorLandscape) | 依赖自动旋转,ROM 可无视 |
| v1.0.24 | 0 (landscape,最严格静态声明) | **仍然被 ROM 强制竖屏** |

**根因**:Godot 预编译模板的 Android 导出在国产 ROM 上存在**无法绕过的兼容性问题**——manifest 写死 landscape 仍被无视,HUD 坐标被 viewport 压缩导致摇杆/按钮点不到。继续 patch manifest 已无意义,**改用 Unity 6 LTS**。

决策依据:
- Unity 是 Android 武侠游戏主流引擎(深岩/老山/饮月之龙均为 Unity)
- Unity Gradle 原生构建,横屏锁定 ROM 无法绕过
- URP 渲染管线对体积雾/PBR 材质/移动端优化成熟

### 2.2 Android 横屏配置(双重保险)

1. **Editor 自动配置** — `Assets/Editor/ProjectSetup.cs`:
   - 首次打开 Unity 时自动执行
   - 设置 `DefaultInterfaceOrientation.LandscapeRight`
   - 禁用 portrait 旋转
   - IL2CPP + ARM64 后端
   - minSdk = 26 (Android 8.0)
   - 切换到 URP 渲染管线
   - 创建所有 Assets 子目录

2. **自定义 Manifest** — `Assets/Plugins/Android/AndroidManifest.xml`:
   - `screenOrientation="landscape"` 写死
   - `resizeableActivity="false"` 禁用 ROM 小窗模式
   - `android:configChanges` 包含 orientation|screenSize 防止重建

### 2.4 CI 配置(双模式)

`.github/workflows/build-unity.yml`:

- **自检模式**(无 Unity 账号):
  - 跑项目结构检查、C# 大括号配对、AndroidManifest 横屏检查
  - 输出手机端 Unity 账号配置指引

- **真构建模式**(配置了 UNITY_EMAIL + UNITY_PASSWORD):

  - `unity-return-license` — 归还 license
  - 上传 APK artifact
  - tag push 时自动创建 Release

## 四、风险与注意事项

### 4.1 模型面数过高
- Lanhwa 1.1M 面、张飞 2.8M 面,必须 Blender 减面到 30-50k 才能在 Android 跑
- 张飞原是胸像,需补全身形

### 4.2 Mixamo 访问限制
- 中国大陆 IP 不可直连 Mixamo,需代理
- 动画资源必须从 Mixamo 获取(无更优免费替代)

### 4.3 Unity Personal License 限制
- 收入/融资超 $20 万美元必须升级 Pro
- 当前阶段免费使用没问题

### 4.4 CC-BY 署名要求
- 发布时需在游戏 credits 署名所有 Sketchfab 作者
